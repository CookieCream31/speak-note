# 議事録テンプレート

[READMEへ戻る](../README.md)

議事録テンプレートはAI Profileと独立して管理します。テンプレートは専用画面（設定の「議事録テンプレート」→「テンプレートを編集」、`/settings/templates`）で編集し、会議作成時と「要約を再生成」で使うテンプレートを選びます。既定テンプレートを設定すると、新しい会議で選択を省略した場合に適用されます。表示テーマは「設定」の先頭から選び、テンプレート画面のヘッダーには重複表示しません。

テンプレートには「リアルタイム」と「確定後」のカード一覧があります。カードの順番・表示状態・名称・AIへの指示（最大2,000文字）と、独自フィールドを設定できます。フィールド型は短文、長文、数値、日付、真偽値、単一選択です。単一選択では選択肢もテンプレートに登録します。

編集画面は左にテンプレート一覧（＋で新規作成、既定には「既定」の印）、右に編集欄、下に保存バーがあります。テンプレート名の横の「既定にする」で既定を切り替え、「リアルタイム」「確定後」の切り替えで編集する構成を選びます。カードは1行の概要（名称・既存項目または独自カード・表示スイッチ）で並び、右端の矢印を押すとカード名・既存項目・AIへの指示・追加項目の編集欄が開きます。並べ替えは左の上下ボタン、既定でないテンプレートの削除は保存バーの「テンプレートを削除」で行います。

テンプレートは保存のたびにrevisionが更新されます。会議作成時にテンプレートの定義をsnapshotとして保存するため、後からテンプレートを編集しても既存会議の表示は変わりません。再生成では会議の保存済み定義か、選び直したテンプレートの現在の版を使用します。解析Versionは今回の定義・名前・revisionをsnapshotに保存し、同じsnapshotをAIへの指示・出力検証・履歴表示に使います。後からテンプレートを編集しても過去の要約は変わりません。Realtime解析ではSession開始時の定義が継続して使われます。

AIが作ったテンプレート値にはTranscriptの根拠を付け、BackendがSegment ID、フィールド型、選択肢を検証します。根拠のない値は不明としてnullになります。カードを非表示にしても、標準の要約・決定事項・Action Item・章などの内部データは保持されます。

会議後要約の主表示は[1つの本文](summary-document.md)です。保存した「確定後」構成の順番・表示状態・タイトル・項目名と値から初期本文を作り、「全文を編集」で全体に追記やメモを加えられます。追加フィールドも文章として編集できます。自由編集した本文はテンプレート定義やAI生成値へ書き戻さず、要約の履歴ごとに保存します。元カードと根拠は「AIの生成内容・根拠を確認」で閲覧できます。会議中のRealtime Snapshotは従来のカード表示を継続します。

既存の会議や旧AnalysisVersionにはテンプレートsnapshotがない場合があります。その場合は従来の議事録表示を使用します。既存の4種類の`summary_format`はテンプレート未使用の旧会議のため保持します。テンプレートを使用する確定生成ではその指示を重ねません。

DB変更はBackend起動時のAlembic Migrationで適用されます。適用手順と確認方法は[運用ガイド](operations.md#apply)、関連コードとテストの場所は[開発ガイド](development.md)を参照してください。


テンプレート管理画面・指示入力欄・議事録カード・Evidence・生成履歴は[表示テーマ](dark-mode.md)に対応しています。テーマ切替は表示の色だけを変え、テンプレート定義・revision・履歴snapshotは更新しません。
