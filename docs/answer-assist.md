# 会議中の回答支援

最終照合: 2026-09-28。既存の会議後質問と別の機能です。回答は発言案であり、実際の発言や確定議事録には追加されません。

## AIを選ぶ・切り替える

1. 「AI設定」でOllamaまたはGeminiの接続・モデル・プロファイルを設定します。回答支援は既存の全プロファイルを選択でき、要約用の会議AIとは独立しています。
2. 「プロジェクト」でプロフィール、背景、参照する資料を保存し、そのプロジェクト内で会議を作成します。既存会議も詳細画面から紐付けられます。
3. 録音または画面共有を開始します。「回答支援」のAIを選び、プロフィール・資料・直近の会話の送信確認にチェックし、「このAIで開始」を押します。
4. 質問を入力して「回答案を生成」、または「今の発言に回答」を押します。「短く生成」で短い口頭回答を依頼できます。詳細・根拠・履歴も確認してください。
5. 自動で生成する場合だけ「会話をAIで確認して自動回答」をONにします。必要なら対象の話者ラベルを選びます。
6. AIを変更すると現在の回答支援を停止します。送信確認をやり直して「このAIで開始」を押します。

開始時のAI接続先・モデル・温度・資料本文と版を固定します。背景や資料を編集したら開始し直してください。後から接続先を変更した場合は、安全のため生成を拒否します。通常の要約、会議後の質問、リアルタイム文字起こしの設定は変更しません。

## ボタンの使い分け

| 操作 | 動作 |
| --- | --- |
| このAIで開始 | 録音開始後、選択したAIで回答支援を有効化します。送信確認が必要です。 |
| 今の発言に回答 | 直近の発言を質問として取り込み、回答案を生成します。途中結果があればそれを優先します。相手の質問が聞こえたときに使います。 |
| 回答案を生成 | 質問欄に入力・編集した内容への回答案を生成します。自分で質問を指定したいときに使います。 |
| 短く生成 | 現在の質問欄の内容について、短い一文を目指す指示で再生成します。表示中の回答を単に短縮するボタンではありません。 |
| 回答支援を停止 | 回答支援だけを停止します。録音・文字起こしは停止しません。 |
| 詳細・根拠を確認 / 回答履歴 | 補足・参照した情報・過去の回答案を開きます。新しいAI生成は行いません。 |

「会話をAIで確認して自動回答」をONにすると、専用Workerが会話を継続して確認し、文脈から完成した質問があるかAIで判断して回答案を生成します。会議中にいつでもON／OFFできます。手動ボタンはOFFでも使えます。普段はOFFのまま「今の発言に回答」、内容を調整したいときは質問欄を編集して「回答案を生成」がおすすめです。

## 制約とプライバシー

- 対応AIは現在の接続実装（Ollama / Gemini）です。OpenAI、Claudeなど任意の外部サービスが自動的に使えるわけではありません。選んだモデルの構造化出力能力や速度に依存し、どのモデルでも同じ品質を保証しません。
- Geminiではデータが外部へ送信されます。Ollamaも設定された接続先へ送信されるため、信頼できる送信先か確認してください。APIキーは保存済み暗号化キーをBackendで使用し、ブラウザには返しません。
- 参照対象は選択プロジェクトと親の背景・対象資料、子または親の共通プロフィール、会議背景、直近の保存済みLive発話です。兄弟プロジェクトや過去会議全文は参照しません。
- 資料は文字列一致で1資料あたり最大約1,800文字の抜粋を選び、合計16,000文字に制限します。会話は直近25発話・合計10,000文字までです。長い資料の重要箇所を必ず取得できる検索ではありません。PDF/Word、ベクトル検索は未対応です。
- 自動回答は初期OFFです。ONの間だけ、専用Workerが新しい発話と直近25発話・最大10,000文字をAIへ送り、文脈から質問の完成と回答の必要性を判断します。最短5秒間隔で予約し、判定・回答が未完了の間は次の判定を待ちます。発話保存とAIの応答時間が加わるため、即時性は保証しません。無音・会話変更なしでは判定を送信しません。同じ発話の文字数が増えた場合も確認対象です。相づち・未完の質問を避ける指示と直近8件の同一文面の重複防止を行いますが、すべての質問の検出・誤検出防止・自分と相手の区別を保証しません。AI判定にも利用料がかかります。「今の発言に回答」はブラウザにある途中結果も利用できます。
- マイクと画面共有の既存の混合音声を使用します。イヤホンでも混合後の音声から自分と相手を完全には区別できず、話者番号は本人確認ではありません。
- 新しい質問を優先し、未実行の古い回答Jobを取り下げます。自動回答をOFFにすると、旧revisionの判定結果や未送信の自動回答は採用しません。すでに送信したAI呼出しの撤回は保証できません。生成中は前の回答を表示し、古い生成結果を最新回答として採用しません。停止後は未送信Jobを送信しませんが、すでに送ったAI処理を撤回できるとは限りません。
- 回答はJobで非同期に生成し、完成後に表示します。トークン単位のストリーミングではありません。AIが入力にない根拠IDを返した場合や根拠を付けなかった場合は、許可されたIDを示して一度だけ再生成します。それでも根拠が不正ならその回答Jobだけ失敗とし、過去の回答・録音・文字起こしは保持します。再試行によってAI呼び出し回数と待ち時間が増える場合があります。誤った回答や根拠の解釈は利用者が確認してください。
- アプリ内のユーザー認証・権限分離は未対応です。機密情報を扱う場合は既存のアクセス制御を設定してください。

## Dockerへの反映

録音と処理中Jobを停止・完了してから、`/home/llm/speak-note` で実行します。

```bash
sudo docker compose restart backend worker realtime-ai-worker frontend
sudo docker compose up -d --build answer-worker
sudo docker compose ps --all
sudo docker compose logs --tail=80 backend answer-worker
```

Backend起動時にMigration `20260927_0022`（回答支援テーブルとJob種別）を適用します。専用 `answer-worker` が必要です。既存Workerの再起動は、新しい回答Jobを汎用Queueで取得しない設定を反映するためです。新しい環境変数・npm依存は追加していません。既存のDB・暗号化キー・LLMタイムアウト・Ollama設定を使用します。データを消す `down -v` やpruneは不要です。

## テスト

```bash
sudo docker compose exec frontend npm run typecheck
sudo docker compose exec frontend npm test -- answer-assist realtime-analysis-panel meeting-review-panel
sudo docker compose run --rm --no-deps --user root backend sh -c \
  'pip install ".[dev]" && pytest tests/test_answer_assist.py tests/test_answer_monitor.py tests/test_knowledge.py tests/test_meeting_questions.py -q'
```

自動テストは外部AIを呼ばず、全Providerの選択、送信確認、録音状態、IDの冪等性、切替による古い送信の防止、送信先変更の拒否、根拠検証、汎用Workerからの分離を検証します。

実機では、ダミー資料に「得意技術はPython」と入力し、録音を開始して「得意技術は？」を生成してください。短い回答・詳細・根拠を確認後、別のAIプロファイルへ切り替え、再確認が必要になることを確認します。古い質問の生成中に新しい質問を送り、古い結果が最新回答を上書きしないことも確認します。自動検出はON/OFFと対象話者を確認します。AIを無効化した場合は回答のみが失敗し、録音と文字起こしが継続することを確認してください。


### 回答の根拠ID再試行を反映する場合

DB変更・依存追加はありません。録音・録画と処理中の回答Jobが終わってから、`sudo docker compose restart answer-worker` を実行します。この変更は新しい回答Jobから有効で、既に失敗したJobは自動再実行しません。回答支援で新しい質問を送り、根拠付きの回答が表示されること、AIが不正な根拠IDを続けて返した場合は失敗表示になり過去の回答が残ることを確認します。

### 今回の自動回答・マイク切替だけを反映する場合

既にMigration 0022とanswer-workerを導入済みの場合、新しいDB変更・依存追加はありません。録音を終了してから `sudo docker compose restart backend answer-worker frontend` を実行し、ブラウザを再読み込みします。

実機確認では、マイクがミュート状態で開始すること、解除後に自分の声が文字起こしへ入ること、再ミュートしても共有元の音声と録音が続くことを確認します。自動回答をONにして会話から質問を発話し、回答案が生成されること、OFF後の新しい発話では自動生成されず手動生成は利用できることを確認してください。
